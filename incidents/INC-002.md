# INC-002: Domain Join Failure due to DNS Misconfiguration

## Executive Summary
* **Incident ID:** INC-002
* **Ticket Reference (GLPI):** #4
* **Category:** Network Services / DNS
* **Target Workstation:** `WIN-USER-01`
* **Severity / Priority:** Medium (P3)
* **ITIL v4 Lifecycle Phase:** Incident Management — Restoration of Service

---

## 1. Incident Description & Detection
Workstation `WIN-USER-01` failed to join the Active Directory domain `genitech.lab`. The system raised an explicit error indicating that the Domain Controller could not be reached.

* **Symptom:** Windows error message: *"An Active Directory Domain Controller (AD DC) for the domain genitech.lab could not be contacted."*
* **Root Cause Analysis (RCA):** The network interface on `WIN-USER-01` was configured with an external DNS server (`8.8.8.8`). Consequently, the client failed to resolve Active Directory SRV records (`_ldap._tcp.dc._msdcs.genitech.lab`).

## 3. Remediation & Workflow Executed

1. **Ticket Logging (GLPI):** Registered incident under `Network Services / DNS`, linked to `WIN-USER-01`, assigned to `it.adam`.
2. **Network Diagnostics:**
   * Checked IP configurations using `ipconfig /all`.
   * Verified DNS resolution failure using `nslookup genitech.lab`.
3. **Remediation (`WIN-USER-01`):**
   * Modified IPv4 properties in `ncpa.cpl`.
   * Set Preferred DNS Server to `192.168.10.5` (`DC01`).
4. **Validation:** Re-attempted domain join via `sysdm.cpl` with domain admin credentials. Workstation successfully joined `genitech.lab`.
5. **GLPI Closure:** Documented solution and marked ticket as **Solved**.

---

## 4. Post-Incident Recommendations
* Ensure DHCP scope automatically provisions `192.168.10.5` as primary DNS for all domain-bound VLANs to eliminate manual IP errors.
